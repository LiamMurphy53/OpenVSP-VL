# Native structural drawing adapter

Landing-gear retraction references resolve the actual native Bogie through GearGeom::GetBogie and call its named SetStowParentID/SetMechParentID and corresponding getters. Local getter symbols use the existing Mach-O symbol-table/loader-slide resolver. GearGeom::UpdateDrawObj and Bogie::LoadDrawObjs supply the native suspension, axis, circle, arrow and strut points; Studio copies their finite XYZ values and native drawing kinds without mechanism equations or Bogie/GearGeom layout replicas. Headless loading additionally calls native UpdateParents, deduplicating GeomBase::AddStepChildID and Geom::Update in dependency order after forward references exist. Missing saved references remain recoverable. Exact implementation source and native/browser/save/Undo/Redo/cold evidence are retained in `.workspace/evidence/gear-retraction-source/` and `.workspace/evidence/gear-retraction-verification.md`. The existing macOS arm64 3.52.2 restriction applies; broader retraction combinations and portable adapters remain open.

The adapter serializes drawing points already generated by the installed, unmodified OpenVSP engine. It calls exported FeaStructure::Update, FeaStructure::GetFeaPart and FeaPart::LoadDrawObjs and SubSurface::LoadDrawObjs functions. It does not construct or evaluate engineering geometry.

The two unmodified vendor headers and their license come from official tag OpenVSP_3.52.2 (commit 8782f46d4399ac04d0a1277d414246bb37035666):

- https://raw.githubusercontent.com/OpenVSP/OpenVSP/OpenVSP_3.52.2/src/util/DrawObj.h
- https://raw.githubusercontent.com/OpenVSP/OpenVSP/OpenVSP_3.52.2/src/util_api/Vec3d.h
- https://raw.githubusercontent.com/OpenVSP/OpenVSP/OpenVSP_3.52.2/LICENSE

The adapter loads the same _vsp.so file used by the Python SDK in the isolated query worker. Exact native layouts are required; native_preview.py accepts only the installed macOS arm64 OpenVSP 3.52.2 configuration. Other platforms/versions report that the preview is unavailable. Portable support is an open delivery requirement.

The local Apple C++ compiler builds the adapter on first use. Content-hashed build files live under .runtime/native-preview. Structural query workers serialize finite native coordinates and leave the saved aircraft unchanged. Drawing connectivity in the browser is display plumbing, not mesh generation. The preview optionally displays the parent aircraft’s native surface samples for context; the native part drawing method returns no separate skin draw objects.

Integration tests cover every listed part family, native global fixed-point positions, symmetry copies, native coordinate changes after edits, invalid owners and byte-exact file preservation. Browser point inspection, aircraft context, refresh, raw drawing downloads and edit/Undo/Redo are verified for the documented fixture. All six fixed-point placement modes independently match native point-mass mesh coordinates at native text precision. Broader independent part surface/CAD comparisons, broader region cases and assembly displays, and portable support remain open before declaring the entire live-preview gate closed.

Section-curve region family changes also call the exported SSXSecCurve::SetXSecCurveType directly. Ordinary regions use native FindGeomForOp/Geom::GetSubSurf; structural regions use native FindFeaStruct/FeaStructure::GetFeaSubSurf. Python validates the native owner/type before calling the curve method. Curve dimensions are existing SDK parameters identified through the native serialized child container. The installed engine creates, copies, bounds and evaluates each new curve. The same platform/version/compiler restriction applies. Native CopyXSecCurve/PasteXSecCurve and ConvertToEdit are now called in one isolated transaction for region copying/conversion. Named ordinary geometry profiles use the official SDK CopyXSecCurve. Dedicated anchors/handles, file-curve imports and broader copy/conversion cases remain open.

Wire geometry previews call the exact exported WireGeom::UpdateDrawObj and WireGeom::LoadDrawObjs methods. Studio copies native point grids, normals, and the WireGeom line object; it excludes native highlights, axes, and other auxiliary drawings. Curve-only and isolated-point imports appear in the aircraft canvas. A separate vehicle-level drawing observer verifies every native point and normal for the tested imports, transformations, trimming, strides, and boundary patches. The exact-version and platform restriction still applies.

Actuator-disk driver guidance uses the exact official PropDriverGroup declaration extracted from VSPAEROMgr.h. Excerpt and full-source hashes are recorded in vendor PROVENANCE.json; the full original header is retained in `.workspace/evidence/VSPAEROMgr-3.52.2.h`. Properly aligned storage is sized from this declaration; exact named native constructor, ValidDrivers and destructor functions execute in the installed engine. All50supported combinations are returned by native validation. Choices persist through official native XML and fresh-process DecodeXml/Update; every engineering equation stays in OpenVSP. The same version/platform restriction applies.

Wing section guidance uses the exact official WingDriverGroup declaration extracted from WingGeom.h, with hashes in vendor PROVENANCE.json and matching full source in `.workspace/evidence/wing-driver-source/`. Aligned storage, the installed named constructor/ValidDrivers/destructor and WingGeom::GetWingSect/WingSect::GetDriverParms provide all 39 supported driver combinations and the actual eleven native parameter IDs. It does not infer IDs from object layout or reproduce wing equations. Independent SDK SetDriverGroup calls verify all 56 candidate combinations. The same exact-version/platform restriction applies; portability remains open.

Body section guidance uses exact XSecCurveDriverGroup/HWXSecCurveDriverGroup/DXSecCurveDriverGroup declarations from XSecCurve.h, with source/excerpt hashes in PROVENANCE.json. Native constructors/validators/destructors enumerate six two-driver and two circular one-driver combinations. A native Area parameter identifies its actual curve container; ParmMgr::FindParmContainer and the installed XSecCurve/CircleXSec::GetDriverParms return original dimension IDs without guessed object offsets. Airfoil::Update fixes drivers to width/chord and thickness/chord, so the UI protects those choices and keeps thickness dimensionless. Full matching source is retained in `.workspace/evidence/body-section-source/`. Body equations and iterative area reconciliation remain in the official engine. The same platform/version restriction applies.

Saved geometry analysis cases call the installed `GeometryAnalysisMgrSingleton::Update` through exported manager-instance and Update symbols. The SDK vehicle update omits this manager, so its native editor update is needed for projection direction, symmetric motion settings and native activity flags. No case equations are copied. Matching source is retained in `.workspace/evidence/intersection-settings-source/GeometryAnalysisMgr.cpp`; native exports were inspected before implementing the adapter. The existing version/platform restriction applies. A separate native Projection analysis and independent direct manager invocation verify the corrected case result.


Attachment frame inspection calls the installed `GeomXForm::GetAncestorAttachMatrix(0)` and `Matrix4d::xform` functions using the exact vendored Matrix4d/vec3d declarations. The native vec3d constructor initializes aligned argument storage. Studio serializes the native column-major matrix and the transformed origin/unit axes; it copies no attachment, coordinate-conversion or rotation equations. Python supplies native parameter activity and names the six official reference enums. Matching implementation source is retained in `.workspace/evidence/attachment-source/Geom.cpp` and `ScreenBase.cpp`; existing header hashes are in vendor PROVENANCE.json. Independent SDK point evaluation checks the native frame origin, and complete SDK parameter/surface comparisons check the resulting transformed geometry. The existing macOS arm64 OpenVSP 3.52.2 restriction applies.


Blade distribution previews call the installed `PropGeom::GetPCurve(int)` and `PCurve::Comp(double)` functions through their exact exported signatures. Only opaque pointers cross the adapter; no PCurve layout or guessed offsets are used. Python validates native geometry/enum identities and requests display samples within native radius bounds. Studio copies scalar native results and uses its existing chart projection. The official matching source and SHA-256 records are retained in `.workspace/evidence/prop-controls-source/`. Independent SDK BladeElement results verify all nine distributions for linear, PCHIP and Bezier interpolation. Native activity and documented profile/integral dependencies guard computed fields. The existing platform/version restriction remains.

Surface-end results copy `Geom::m_CapUMinSuccess` and `m_CapUMaxSuccess` for each native main surface. Their inline public getters have no emitted engine symbol. `tools/generate_cap_layout.py` compiles the complete, unchanged official Geom declarations with their matching Code-Eli/Eigen dependencies to generate `GeomCapLayout.h`. Only unused CAD export pointer types are forward-declared; no Geom data fields or engineering equations are replaced. Exact input and generated hashes are recorded in vendor PROVENANCE.json. Before reading either vector, Python verifies the exact engine binary SHA-256 and the adapter verifies five native Parm addresses against the generated layout, rejects mismatched surface counts, and reports an absent vector as unavailable. Existing macOS arm64/OpenVSP 3.52.2 restrictions apply. A false result means the engine did not add a cap; it does not establish why. Profile LE/TE shaping has no equivalent result flag here.

Independent validation compiled the original Geom inline getters directly against all matching headers and compared 30 cases (five cap modes across WING, POD, FUSELAGE, STACK, PROP and ELLIPSOID) with the guarded bridge. Exact source, compiler probe, getter oracle and results are retained under `.workspace/evidence/cap-status-source/`. Native cap editing tests also verify complete geometry, saving, profile edges and study constraints. Layout generation requires the matching source/dependency inputs listed in PROVENANCE.json; the generated layout is development tooling, and end users do not need those headers to launch the packaged application.


Custom GUI definitions also copy the original GuiDef::m_Range (17 significant digits; non-finite ranges become null). No slider/geometry equations execute in the bridge. The browser uses the declared range only to present a bounded slider window beside the existing numeric field; all actual edits retain current binding, activity, driver and property-lock validation in the native worker. The existing exact GuiDef declaration/version restriction remains unchanged.
