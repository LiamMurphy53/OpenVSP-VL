# Native structural drawing adapter

Landing-gear retraction references resolve the actual native Bogie through GearGeom::GetBogie and call its named SetStowParentID/SetMechParentID and corresponding getters. Local getter symbols use the existing Mach-O symbol-table/loader-slide resolver. GearGeom::UpdateDrawObj and Bogie::LoadDrawObjs supply the native suspension, axis, circle, arrow and strut points; Studio copies their finite XYZ values and native drawing kinds without mechanism equations or Bogie/GearGeom layout replicas. Headless loading additionally calls native UpdateParents, deduplicating GeomBase::AddStepChildID and Geom::Update in dependency order after forward references exist. Missing saved references remain recoverable. Exact implementation source and native/browser/save/Undo/Redo/cold evidence are retained in `.workspace/evidence/gear-retraction-source/` and `.workspace/evidence/gear-retraction-verification.md`. The existing macOS arm64 3.52.2 restriction applies; broader retraction combinations and portable adapters remain open.

The adapter serializes drawing points already generated by the installed, unmodified OpenVSP engine. It calls exported FeaStructure::Update, FeaStructure::GetFeaPart and FeaPart::LoadDrawObjs and SubSurface::LoadDrawObjs functions. It does not construct or evaluate engineering geometry.

The two unmodified vendor headers and their license come from official tag OpenVSP_3.52.2 (commit 8782f46d4399ac04d0a1277d414246bb37035666):

- https://raw.githubusercontent.com/OpenVSP/OpenVSP/OpenVSP_3.52.2/src/util/DrawObj.h
- https://raw.githubusercontent.com/OpenVSP/OpenVSP/OpenVSP_3.52.2/src/util_api/Vec3d.h
- https://raw.githubusercontent.com/OpenVSP/OpenVSP/OpenVSP_3.52.2/LICENSE

The adapter loads the same _vsp.so file used by the Python SDK in the isolated query worker. Exact native layouts are required; native_preview.py accepts only the installed macOS arm64 OpenVSP 3.52.2 configuration. Other platforms/versions report that the preview is unavailable. Portable support is an open delivery requirement.

The local Apple C++ compiler builds the adapter on first use. Content-hashed build files live under .runtime/native-preview. Structural query workers serialize finite native coordinates and leave the saved aircraft unchanged. Drawing connectivity in the browser is display plumbing, not mesh generation. The preview optionally displays the parent aircraft’s native surface samples for context; the native part drawing method returns no separate skin draw objects.

Integration tests cover every listed part family, native global fixed-point positions, symmetry copies, native coordinate changes after edits, invalid owners and byte-exact file preservation. Browser point inspection, aircraft context, refresh, raw drawing downloads and edit/Undo/Redo are verified for the documented fixture. All six fixed-point placement modes independently match native point-mass mesh coordinates at native text precision. Broader independent part surface/CAD comparisons, broader region cases and assembly displays, and portable support remain open before declaring the entire live-preview gate closed.

Surface-end results copy `Geom::m_CapUMinSuccess` and `m_CapUMaxSuccess` for each native main surface. Polygon snapshot inspection copies the original PGMulti live graph using the unchanged official PGMesh.h and compiler-derived NGonLayout.h. Before access, Python verifies the exact engine checksum and geometry type; the adapter verifies the original Scale_From_Original Parm address. Snapshots use stable list-order indices instead of process pointers and preserve local full-precision coordinates, scale matrix, live connectivity, parent/child faces, alternate triangles, node tag/UW maps, mesh levels, wakes, regions and part/tag metadata. Unordered maps are sorted for deterministic comparison; dangling/outside-live-graph references and undefined doubles reject. Snapshot capture is read-only. Restoration builds a separate PGMulti through the original native constructors and AddPoint/AddMesh/AddNode/AddEdge/AddFace methods, restores graph fields and native matrix, validates the staged graph through original Check methods, then swaps live ownership. Original destructors dispose of the old graph. Python validates ownership and reciprocal references before encoding an in-memory XML transport; XML uses no DTD or external entities. System libxml2 parses that transport. Pending garbage objects outside the live graph are not serialized. Studio now embeds checksummed snapshots in VSP3 geometry nodes and restores them after native loading. Project writes, history files and native analysis model artifacts retain these snapshots; the native Gmsh exporter supplies polygon preview triangles. Original OpenVSP ignores the extension. Coarsened-level coverage and the remaining native polygon operations are unfinished.

Triangle-to-polygon setup calls the original global SubTagTris(true, MeshGeom::m_TMeshVec, empty region selection) before the official CreateNGonMeshGeom SDK call. This does not recover triangle quad/reference/UV metadata omitted by native MeshGeom serialization; full live-session conversion parity remains open.

Live triangle conversion metadata can now be read through studio_mesh_metadata/native_ngon.mesh_metadata. The complete unchanged official TMesh.h supplies node/triangle/component declarations, guarded by the pinned engine checksum and original MeshGeom scale Parm address. Capture includes per-corner raw coordinates/UW/coordinate flags, original triangle quad/reference/tag/normal/density/inside flags and split hierarchy, component origin/surface/plate/copy/material/CFD/shell/group attributes, interpolation grids and the actual native scale matrix. Triangle metadata restoration is now available as a lower-level primitive. It stages values on original native TMesh::copy clones, validates unchanged triangle counts/XYZ/normals and shared-node consistency, then swaps only passive metadata into existing native objects. Native node/triangle/edge ownership is retained. Split hierarchies currently reject explicitly; they must be canonicalized/reconstructed through native routines before project integration. Metadata schema2 adds the complete original SubSurfaceMgr part/tag tables, which cannot be recovered reliably by re-tagging a joined saved mesh. Archived tables bind to actual source metadata with a digest excluding native scratch IDs and uniform scale. Conversion restores those original tables before the SDK call; source changes invalidate the archive. Table restoration stages all containers before no-throw swaps. The complete SubSurfaceMgr declaration replaces only unused includes with forwards; protected access is exposed only in the adapter. Every field and its424-byte size are statically checked against a separately compiler-generated layout from the untouched original complete header. Exact engine checksum, original MeshGeom Parm address and initialized native singleton guard remain required. Project embedding/loading is still unfinished.

### Saved-airflow OpenMP runtime

The original-source reader and pitch recorder use OpenMP with one thread and O3/DNDEBUG. Serial builds differ from the installed solver on a retained multi-condition pitch case. `openmp_runtime.json` pins the official Homebrew libomp 23.1.3 macOS arm64 bottle and the extracted header, library and license hashes. `native_openmp.py` verifies `.runtime/openmp` before build/use/packaging. Runtime binaries are excluded from Git; the packager copies the verified runtime and license plus prebuilt recorder/reader executables. The Homebrew library is unmodified. Each executable's load reference is relocated to `@rpath/libomp.dylib`, using `@loader_path/../openmp/lib`, and ad-hoc signed. No global OpenMP installation is needed. This new runtime has been verified on the current host; broader macOS deployment compatibility remains unproved.

Version-two evaluated-state companions add lossless edge circulation at every computational/coarser grid level. Python validation binds the companion to its original ADB and case list; native restoration additionally checks actual time, loop and edge dimensions. Version-one companions remain readable. This integrity mechanism does not authenticate externally forged state and does not certify solver convergence.
