# OpenVSP Studio — native engine workspace

The current workspace focuses on autonomous aircraft. Human/crew creation and dedicated editors are hidden for now; existing native components remain readable and editable through their parameters.

An independent modern interface over the **official, unmodified OpenVSP 3.52.2 engine**. Aircraft geometry, parameter dependencies, fitting and analyses are evaluated by OpenVSP. The browser displays native geometry and results. Full workflow parity remains under development; see [FEATURE_STATUS.md](FEATURE_STATUS.md) and [CAPABILITY_PLAN.md](CAPABILITY_PLAN.md) for verified coverage and remaining work.


Polygon-mesh projects include a checksummed Studio snapshot inside the `.vsp3` file. Studio restores the native polygon graph when reopening, editing or undoing changes. The original OpenVSP 3.52.2 reader ignores this extra data, and saving through that application discards it. Use the native VSPGEOM export and its companion files for polygon data in other tools. Polygon coarsening and other specialized operations remain under development.

Select a triangle mesh in **Modeling tools → Components & sets → Create polygon mesh** to create a separate native polygon component. The source remains in the project. After running **Component areas and volumes**, download `component-mesh.vsp3` from the run's files and open it in Studio to work with the generated mesh. Studio saves preserve its native conversion metadata through reopening and property edits. For a polygon component, **Components & sets → Triangulate polygon mesh** applies OpenVSP’s native triangulation to its active mesh level; Undo restores the polygons. **Native polygon report** displays OpenVSP’s original tag, mesh-count and non-manifold edge report without changing the saved aircraft. Older files saved without that metadata still use original native tag setup and cannot recover information already discarded by native serialization. Body, wing and intersecting body/wing conversion checks pass. The browser artifact workflow, conversion, Undo/Redo and reload are verified for a wing; broader source coverage remains open.

## Workspace layout and modeling controls

Use **Panels** to hide or reopen panels and reset the current tab’s layout. Drag a panel title onto another panel to exchange their positions, or use its left/right buttons. Drag a panel edge to resize it. The maximize button gives that panel the available workspace; **Restore panels** or Escape returns to the previous arrangement. Design, Modeling tools, Analyze, and Studies remember their own panel order, widths, and closed panels in this browser. Small screens stack the panels and retain move, close, and maximize controls.

**Scroll** zooms, **left-drag** rotates, and **middle-drag** (hold the scroll-wheel button) pans without rotating. Horizontal rotation retains the requested inversion. Fit resets the zoom and pan. The XYZ arrows in Design’s corner show the viewing orientation.

Geometry display defaults to **feet and degrees**. The **Units** button chooses the meaning of one native model unit and the length/angle display units. Labeled Design dimensions and wing metrics convert for display; geometry edits convert back before reaching OpenVSP. Ratios and normalized coordinates stay unchanged. Other tools, analyses, and downloads keep their native unit conventions. These preferences are browser-local, so check the model convention when loading a different aircraft. OpenVSP supports [unitless geometry conventions and explicit engineering unit choices](https://openvsp.org/pyapi_docs/latest/groups/Enumerations.html); changing Studio’s display does not rescale an existing aircraft.

Everyday Design controls appear first: size and placement, wing section dimensions, cross-sections and profiles, then additional native geometry and airfoil groups. Common parameters within a group precede less-used settings. The Modeling tools navigator puts components, airfoils, sections, controls, propellers, measurements, and file tools before specialized engineering editors.

For wings, **Wing section dimensions** selects an independent section and its three native dimension drivers. Choose among span, area, aspect ratio, taper, average/root/tip chord and secondary sweep, then **Apply section drivers**. OpenVSP validates the combination and computes the other dimensions, which appear under **Calculated section dimensions**. Sweep, dihedral and twist stay beside the editable dimensions; their reference choices and chord-fraction locations are below. Root profile zero follows the first section rather than providing another independent section. Overall projected span is editable; overall aspect ratio is an engine output. Calculated dimensions are protected in Design and saved studies. Driver changes, edits and Undo/Redo persist in the native aircraft. Verification and remaining geometry coverage: `.workspace/evidence/wing-controls-verification.md`.

For fuselages and stacks, **Body section dimensions** follows the section selected in **Cross-sections & profiles**. Choose two drivers among width, height, area and height/width, or one driver among diameter and area for circles. Point profiles have no width/height controls. Airfoil profiles use OpenVSP's fixed chord and thickness/chord drivers; thickness/chord remains a ratio. Calculated dimensions stay readable and protected in Design and studies. **Section position & rotation** uses fractions of body length for fuselages and offsets from the previous section for stacks, plus section rotation in the selected angle units. Width, height and area use the selected display units. Body driver/area/position/rotation edits, four-step Undo/Redo and reopening have independent SDK evidence in `.workspace/evidence/body-controls-verification.md`; broader shape/attachment/import combinations remain open.

**Attach to another component** in Design chooses a parent, then separate position and rotation references: no attachment, parent axes, surface U/W, section R/S/T, uniform L/M/N or wing eta/M/N. Open the applicable coordinate groups to choose normalized or native section coordinates, or distance along the parent for L. Calculated coordinates remain protected; joint parents supply their native joint frame. **Show attachment axes in model** displays OpenVSP's frame before Placement offsets, and **Attachment frame** reports its global origin and downloads the native matrix/axis points. Global Placement preserves world coordinates when attachments change; relative Placement follows the frame. Surface attachments use the parent's first main surface. The engine falls back to component axes without a surface and interprets eta as L for a parent other than a wing. Parent changes and coordinate edits support Undo/Redo and native saving. Verification and remaining scope: `.workspace/evidence/attachment-verification.md`.

New component controls in Design cover ellipsoid radii, hinge motion/orientation/travel limits, conformal offsets/trimming, body section ordering and wing airfoil orientation. Creation uses readable component names and requires a surface source for conformal geometry. This implementation batch has basic native loading and browser checks; extended verification remains queued (`.workspace/evidence/drone-family-implementation.md`).

Design now groups **Symmetry & repeated components** and **Mass inputs** beside the main dimensions. Symmetry choices use native planes, axes and ancestor frames; point-mass XYZ is component-local. Mass, density and inertia retain native units. Propeller **Individual blade spacing & balance** and **Blade folding** expose the original native modes, angles and fold axis. These new controls have basic load/render checks; extended native comparisons and recovery checks are queued for the implementation-first phase (`.workspace/evidence/drone-modeling-implementation.md`).

For propellers, **Size & shape** chooses pitch at three-quarter radius or feather angle as the native pitch driver. **Blade arrangement & pitch references** controls representation, azimuth, pre-cone, reversal, cylindrical sections and pitch-axis references; its calculated values stay protected. **Blade profile station** selects a native airfoil/profile and its radius fraction. **Blade distributions** edits chord/radius, twist, thickness/chord, design lift, rake/radius, skew/radius, sweep, axial/radius and tangential/radius. The plots use OpenVSP's own curve evaluation. Open **Edit control points** to apply interpolation, edit native points or insert/remove stations. Fixed/calculated stations are locked. **Download curve samples** saves native parameters and samples at full precision; downloads retain degrees and dimensionless ratios even when the browser displays radians. The existing Modeling tools → Propellers editor also uses native plots and locked stations. Verification and remaining scope: `.workspace/evidence/prop-controls-verification.md`.

## Run on this Mac

Open **OpenVSP Studio.app** in this project folder to start the modern interface and open it in your browser. **OpenVSP.app** opens the original OpenVSP editor. Keep the Studio shortcut with the whole project and its `.runtime` folder; it is not a standalone distributable application yet.

The Studio launcher checks that the original engine loads and the modern modeling adapter executes an original native query in an isolated process, reuses a matching running Studio server, and reports port conflicts without replacing other processes. New servers lock their workspace against a second server on another port. Older servers started before this change do not have that lock: stop those servers before starting a new one on the same workspace. You can keep using an existing older server at its current address.

For startup checks or a separate workspace:

```sh
.runtime/python-interpreters/cpython-3.11-macos-aarch64-none/bin/python3 studio_launcher.py --check
.runtime/python-interpreters/cpython-3.11-macos-aarch64-none/bin/python3 studio_launcher.py --port 8794 --workspace /path/to/separate-workspace
```

`--no-open` starts or reuses the server without opening a browser. Server logs are saved as `studio-server.log` in the selected workspace. `OPENVSP_WORKSPACE` selects the workspace for both the server and launcher; `OPENVSP_HOME` and `OPENVSP_PYTHON` select an existing original distribution and matching Python. The native drawing adapter still requires the documented macOS arm64 OpenVSP 3.52.2 configuration. Cross-platform packaging remains unfinished.

You can also start the server directly:

```sh
python3 server.py
```

Open <http://127.0.0.1:8765>. Set `PORT` to use another local port. The server listens only on localhost. The project-local official distribution, compatible Python 3.11 and NumPy in `.runtime/` are found automatically without modifying system Python.

The native aircraft is `.workspace/aircraft.vsp3`. **Save .vsp3** downloads a portable model; **Open .vsp3** loads a native model. Edits use native-file transactions, support Undo/Redo, and reject stale edits from another window. Undo chains last for the server session; snapshots stay on disk. Each analysis uses a separate model copy and retains its native files, request, log and results in `.workspace/jobs/<run-id>/`.

The installed engine's 21 registered analyses are available, plus the native structural assembly mesh workflow and five native reference calculation workflows. Registered analysis inputs/defaults/descriptions come from the engine. Reference starting inputs and labels are provided by Studio; all reference geometry and engineering values come from the native API. Runs provide logs, cancellation, native tables, selectable plots and JSON/CSV/native-file downloads. Saved history survives refresh and restart; interrupted runs are labeled.

Standalone SurfaceIntersection runs display saved native curves, including empty-result recovery. **Surface intersections and CAD** now guides every native SurfaceIntersection analysis input: named sets/modes, normal/thin surfaces, region inclusion, native tolerance, raw/adapted samples, all five native formats, CAD units/labels and STEP shell/BREP choices. CFD and FEA mesh viewers display native Gmsh coordinates/connectivity, regions, beams/points and native element IDs. Orbit/zoom, region visibility, edges/transparency, whole-element cuts, inspection and fullscreen controls are available. Higher-order previews use corner nodes. Cuts select elements by their centers and do not invent cut faces. Unsupported elements are counted. Very large files remain downloadable when preview limits are exceeded.

VSPAERO prepares native geometry before solver execution. Completed runs can display native surface pressure, wakes and velocity/pressure flow-plane files. Case selection, field/range controls, element inspection, display cuts and PNG snapshots are available. Display interpolation is not a substitute aerodynamic solver. CpSlicer can run from a saved solution with source-model/solution provenance, and provides native slice values and plots.

**Reopen saved aerodynamic results** and **Pressure slices from a saved solution** have dated source selectors with model revision labels. Reading previous results uses OpenVSP’s native file parser without rerunning the solver. Slice positions accept comma- or space-separated coordinates along X, Y and Z, including empty unused axes. Every displayed axis is sent explicitly so defaults from the saved aircraft cannot silently add other planes. Native slice plots preserve each saved case and sample block, with full coordinate/pressure tables and SVG, JSON and CSV downloads. Source solutions and the current aircraft are preserved. Two native workflow tests and three actual browser runs have independent native comparisons, including a three-angle sweep; see `.workspace/evidence/saved-solutions-verification.md`. Unsteady/thick mixed case coverage and external saved-file imports remain open.

Mass properties, cross-sectional areas, projected area, wave drag and parasite drag have guided setup with readable native choices and limits. Geometry/mode, projection target/direction/boundary, automatic/manual slicing and parasite reference controls show the fields that apply to the selected option. All native inputs remain in the saved request. Results include native component mass/inertia, slice areas/centroids, projection outlines, cone-section area plots and drag buildup. Mass setup links to each component’s native density, shell and point-mass editor. Returning to Analyze refreshes aircraft settings while preserving the draft inputs. Wave setup saves an entered reference area or copies the current native wing area as an undoable aircraft edit; it stays fixed until edited or copied again. Parasite setup offers native length/airspeed/atmosphere/friction choices and exports OpenVSP’s original buildup CSV. Atmosphere choices determine which supplied properties drive the run; inspect the saved native flight-condition results for values the engine actually used.

**Reuse saved analysis inputs** restores a guided run’s setup for the current aircraft. For pressure slices and reopening saved aerodynamic results, it also restores the selected source solution; those operations use that solution’s saved aircraft and copied native files. ## Components and geometry sets

**Modeling tools → Components & sets** shows the native hierarchy. Choose a component and use First, Move up, Move down or Last to change its position among siblings. Parent changes retain OpenVSP's attachment relationships; native attachment parameters remain in Design.

Named sets support membership edits, names, appending an empty or copied set, and replacing a set's membership from another named or built-in set. Copying membership keeps the destination name and attributes. Sorting by name only changes the list display; native references retain their indices.

**Transform a group** moves, rotates, scales, or applies a combined transform to a chosen native set. Translation uses model units; rotation uses degrees about native global axes. The combined operation can also scale component translations. The bounds displayed before and after each edit come from OpenVSP. Attached components follow its rules: an attached nonmember can follow a parent's move/rotation, while native ScaleSet scales selected geometry. Inspect the updated surfaces in Design. Undo reverses one complete operation.

**Native set count** reads the engine's limits (20–997 user slots in this distribution). Increasing the count appends slots. Reducing it removes trailing slots and their attributes. The editor lists affected native settings, modes and preset values and requires valid replacement sets. Dependent edits and preset applications that leave references to removed slots are rejected before committing the aircraft. An open analysis draft using a removed set requires an explicit replacement; Undo restores its choice when the slot returns. Native undo/redo restores geometry, membership, names and metadata. Arbitrary reordering of slot contents is not yet provided.

## Design studies

**Studies** saves a named native aircraft snapshot with ordered analysis steps. Add aircraft-parameter sweeps or native analysis-input sweeps: numbers, text, named native options, complete XYZ vectors, individual vector coordinates and entire input arrays. Array cases can have different lengths, including empty arrays where the native input permits them. Case editors support adding, duplicating, removing and reordering values without splitting text at commas or spaces. All value combinations become cases (up to 1,000), and every calculation runs through the official engine. Input settings you change are explicit overrides. **Save all displayed inputs as explicit settings** also stores unchanged inputs; otherwise each case reads its native aircraft settings. A partial element or coordinate sweep preserves each case’s other native values; an entire-array sweep replaces that array. Overlapping sweep dimensions are rejected. Sweeps override those saved settings. Aerodynamic solver steps prepare their native geometry automatically. CpSlicer and previous-analysis reading can use an earlier aerodynamic step in the same case.

Saving an existing study can keep its saved aircraft or capture the current aircraft. Older executions retain their original definition and aircraft. Editing a study requires saving before starting another execution. Choose a native result field to compare every case’s exact samples, requested sweep values and values the engine actually applied. The plot shows one selected native sample against a native sweep value or case number. Missing or undefined values remain unavailable; structured fields retain their complete arrays in the table and CSV. Named options display readable labels while downloads keep the original native codes and IDs. If an analysis replaces a swept native parameter object, its last native value before execution remains recorded, the value after execution is marked unavailable, and the comparison and CSV include a setting note.

Each execution saves case aircraft, native runs, inputs, outputs and attempts. **Resume unfinished cases** retains successful steps and retries unfinished ones. Cancellation and partial failures stay visible. A recovered server detects workers that are still alive, waits for those workers and reuses finished cases; it does not launch duplicate runs. CSV and SVG exports and complete native aircraft/result bundles are available. See `.workspace/evidence/studies-verification.md` for the verified cases and remaining limits.

Study fields wait until loading or saving finishes before accepting edits. A rejected case shows unstarted calculations as **Not run**, with the original error and unavailable results; completed calculations retain their native runs. Correcting and saving a definition creates a new execution while keeping the earlier history. A browser-created body-profile/chevron study, corrected coverage study, exact native geometry/results/meshes, downloads and cold reopening are documented in `.workspace/evidence/profile-chevron-study-verification.md`.

In **Modeling tools → Propellers**, **Save all rotor speeds** keeps the current rotating groups’ RPMs and linked/independent setting in the native aircraft before representation changes. **Restore saved rotor speeds** applies them after the same components and native surface copies return. Different rotor membership requires restoring the prior representation, aerodynamic selection and symmetry, or saving the new speeds. Both actions support Undo/Redo; saved speeds persist when reopening the aircraft.

**Save all disk settings** separately keeps each actuator disk’s three driver choices, driving values and automatic/manual hub setting in the native aircraft. **Restore saved disk settings** matches the original components and native surface copies, restores those inputs, and lets OpenVSP calculate outputs using the current geometry, airspeed and density. Missing or extra disks, invalid saved inputs and a manual hub larger than the current diameter prevent restoration. Save/restore support Undo/Redo and reopening. Saved study parameter identities still require their own recovery workflow.

## Files and persistence

For a saved rotor study after representation changes, use **Studies → Review current aircraft and match rotor fields**. Studio matches recreated native fields by the original component and surface membership, keeps the sweep values, and validates current drivers and limits. Review changes the draft only; **Save study** captures the reviewed aircraft as its new baseline. Earlier executions retain their own aircraft. Missing or ambiguous rotors, newly calculated disk fields and a changed aircraft revision prevent recovery. Switching back to the saved aircraft restores the prior field bindings. Representation changes inside an individual case still require separate studies when the swept rotor disappears.

Import & export provides 21 active native export formats and nine import options. CAD settings, geometry sets, modes, selected structures, propeller blade-element files and airfoil companion bundles are available. The four historical enums FELISA, AWAVE, VORXSEC and XSECGEOM have no active exporter in this engine and are not offered as working exports. Native .vsp3, .fit, DES and XDDM workflows are separate.

Fixed-point parts use **Apply placement** to save the mode, reference, coordinates, offsets and mass settings as one native transaction. Parent U/W coordinates use OpenVSP's part mapping; component-origin and center-of-gravity offsets follow the reference component's frame. The engine determines point positions, mirrored copies and mass conversion. Missing active references are rejected, and deleting a referenced parent/component requires choosing a replacement. Undo/Redo and reopen retain the native references.

Structural runs with point masses also export a native NASTRAN companion. OpenVSP 3.52.2 counts point masses in Gmsh's element total but omits their element records; the viewer reads their native nodes and masses from the companion's CONM2 records and displays an explanation. Native downloads retain their original bytes. The `.bdf` download is the bulk solver deck and `.dat` is its native SET companion. Single-structure and assembly cases are verified. See `.workspace/evidence/fixed-points-verification.md` for independent engine and browser evidence.

OpenVSP's design-variable list and fitting targets/variables need additional persistence between isolated workers. The interface stores references in native typed attributes and restores them through official APIs. A few string references/point lists lacking setters use the matching native XML format, followed by a fresh engine reload; calculations remain native. Temporary structural CAD evaluation initializes arrays before native expansion because `Update()` alone does not evaluate structure surfaces.

Normal server restarts now retain the verified aircraft revision and native undo/redo snapshots. An inconsistent or missing history snapshot preserves the session record for recovery and displays a warning; it does not silently apply an unrelated aircraft.

### Property locks

Use **Lock** beside a geometry property to hold its current native value. Locks are saved in the aircraft file. Aspect ratio also has a lock in Streamlined wing design; Pro exposes locks on the native geometry fields, including calculated dimensions. **Unlock** releases the constraint.

Studio checks the final native result before saving: direct edits, related dimensions, parameter links, fitting and prepared study cases cannot change a locked value or remove its parameter. A warning identifies the conflicting property and the edit is discarded. Locks constrain Studio transactions; the original OpenVSP application does not enforce Studio attributes.

The **Aircraft property locks** list in Properties shows all saved constraints and lets you release them. Missing properties or values changed outside Studio are flagged, including when the aircraft has no remaining components.
